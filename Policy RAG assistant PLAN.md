# PolicyAssistant — Implementation Plan

A RAG (retrieval-augmented generation) application in C# that answers employee questions about company policies (HR, expenses, leave, IT, code of conduct), grounded in documents indexed in Azure AI Search, with answers generated by a chat model deployed in Microsoft Foundry (formerly Azure AI Foundry). Every answer must cite its sources.

This plan is written to be executed by Claude Code, phase by phase. Complete each phase, verify its acceptance criteria, and stop for review before starting the next.

---

## 1. Tech stack

- .NET 9 (C#), solution with multiple projects
- ASP.NET Core minimal API (backend)
- Blazor Web App, interactive server render mode (frontend)
- Azure AI Search — hybrid (keyword + vector) search with semantic ranking
- Microsoft Foundry — chat model deployment + embedding model deployment
- Azure Blob Storage — source documents
- NuGet: `Azure.Search.Documents`, `Azure.AI.OpenAI`, `Azure.Identity`
- Tests: xUnit, NSubstitute (or Moq), FluentAssertions
- Use the latest stable versions of all packages; do not use prerelease packages unless a required API only exists there (note it in the README if so).

## 2. Azure prerequisites (created manually, not by Claude Code)

These resources are created in the Azure portal before Phase 1. Claude Code should not attempt to provision them, but should document them in the README.

| Resource | Details |
|---|---|
| Foundry project | Chat deployment (e.g. `gpt-4.1-mini`) and embedding deployment (`text-embedding-3-small`) |
| Azure AI Search | Basic tier or higher, semantic ranker enabled |
| Storage account | Blob container named `policies` containing the policy PDFs |
| Search index | Created via the portal's "Import and vectorize data" wizard over the `policies` container, using the embedding deployment. Add a semantic configuration named `default`. |

Default field names produced by the wizard (make these configurable, do not hardcode):
`chunk_id` (key), `parent_id`, `chunk` (text), `title`, `text_vector` (vector).

Role assignments for local development (signed-in developer via `az login`):
- Search Index Data Reader on the Search service
- Cognitive Services OpenAI User on the Foundry resource

## 4. Engineering conventions

- **No secrets in code or config.** Authenticate everything with `DefaultAzureCredential`. No API keys anywhere.
- **Options pattern** for all configuration (`SearchOptions`/`OpenAIOptions` style classes bound from `appsettings.json`, validated on start with `ValidateDataAnnotations().ValidateOnStart()`).
- **Interfaces around external services** so the RAG logic is unit-testable: `IRetriever`, `IAnswerGenerator`, orchestrated by `IChatService`.
- Register Azure SDK clients as singletons.
- Async all the way, pass `CancellationToken` through.
- Structured logging with `ILogger`; log retrieval count, top scores and token usage, never full document content at Information level.
- Nullable reference types enabled, warnings as errors.
- Keep prompts in a single dedicated class (`Prompts.cs`) rather than scattered strings.

## 5. Configuration

`PolicyAssistant.Api/appsettings.json` (values filled in locally via `appsettings.Development.json` or user secrets — endpoints only, no keys):

```json
{
  "AzureSearch": {
    "Endpoint": "https://<search-service>.search.windows.net",
    "IndexName": "<index-name>",
    "SemanticConfigurationName": "default",
    "ContentField": "chunk",
    "TitleField": "title",
    "VectorField": "text_vector",

```

`PolicyAssistant.Web` needs only the API base URL.

## Phase 1 — Solution scaffold

**Tasks**
1. Create the solution and projects per section 3, with project references: Api → Shared, Web → Shared, Api.Tests → Api.
2. Enable nullable, implicit usings, warnings as errors in a `Directory.Build.props`.
3. Add a `.gitignore` for .NET and a `.editorconfig`.
4. Add a `/health` endpoint to the API.
5. Create a README skeleton with the prerequisites from section 2 and run instructions.

**Acceptance criteria**
- `dotnet build` succeeds with zero warnings.
- `dotnet run` for the API serves `/health` returning 200.

## Phase 2 — Shared contracts

**Tasks**
Define in `PolicyAssistant.Shared`:
- `ChatRequest` — `string Question`, `IReadOnlyList<ChatTurn>? History` (history unused until Phase 6)
- `ChatTurn` — `string Role` ("user" | "assistant"), `string Content`
- `ChatResponse` — `string Answer`, `IReadOnlyList<Citation> Citations`, `bool IsGrounded`
- `Citation` — `int Number`, `string Title`, `string Snippet`, `string ChunkId`

Use `record` types.

**Acceptance criteria**
- Builds; types are immutable records.

## Phase 3 — Retrieval and generation API

**Tasks**
1. **Options classes** for `AzureSearch` and `AzureOpenAI` sections with validation.
2. **`IRetriever` / `AzureSearchRetriever`**
   - Runs a single hybrid query: full-text query on the question + `VectorizableTextQuery` (server-side vectorization using the index's vectorizer) on the vector field, `QueryType = Semantic` with the configured semantic configuration.
   - Returns `Top` results as a `RetrievedChunk` model (`ChunkId`, `Title`, `Content`, `RerankerScore`).
   - Drops results with a reranker score below a configurable threshold (default `1.5`, add to options).
3. **`IAnswerGenerator` / `AzureOpenAIAnswerGenerator`**
   - Uses `AzureOpenAIClient` (with `DefaultAzureCredential`) → `GetChatClient(ChatDeployment)`.
   - Builds messages: system prompt from `Prompts.cs` + user message containing numbered sources (`[1] Title: ...\nContent: ...`) and the question.
   - System prompt requirements: answer only from the provided sources; cite sources inline as `[n]`; if the sources do not contain the answer, reply with a fixed "I couldn't find that in the company policies." message; be concise; never invent policy details.
4. **`IChatService` / `ChatService`** — orchestrates: retrieve → if zero chunks, return the "not found" response without calling the model → otherwise generate → map cited `[n]` markers in the answer to `Citation` objects (only include sources actually cited) → set `IsGrounded`.
5. **Endpoint** `POST /chat` accepting `ChatRequest`, returning `ChatResponse`. Validate that `Question` is non-empty and under 1,000 characters; return 400 otherwise.
6. Enable OpenAPI/Swagger in Development.
7. Add `requests/chat.http` with 5 sample questions, including one that should not be answerable.
8. Add CORS allowing the Web project's local origin.

**Unit tests** (`PolicyAssistant.Api.Tests`, mocking `IRetriever` and `IAnswerGenerator`)
- No retrieved chunks → returns "not found" answer, generator not called.
- Answer containing `[1]` and `[3]` → citations contain exactly sources 1 and 3.
- Answer with no citation markers → `IsGrounded = false`.
- Invalid request → 400.

**Acceptance criteria**
- All tests pass.
- With Azure resources configured, `chat.http` requests return grounded answers with citations, and the out-of-scope question returns the "not found" message.

## Phase 4 — Blazor chat UI

**Tasks**
1. Typed `HttpClient` (`PolicyAssistantApiClient`) calling `POST /chat`.
2. Single chat page:
   - Scrolling message list (user and assistant bubbles).
   - Input box + send button; Enter to send; disabled while a request is in flight; loading indicator.
   - Inline `[n]` markers rendered as clickable badges; clicking shows the citation's title and snippet in an expandable panel below the answer.
   - Friendly error message on API failure.
3. Clean, minimal styling in the component's CSS isolation file; no heavy UI libraries.

**Acceptance criteria**
- Running Api and Web together, a user can ask questions and expand citations.
- UI is usable at mobile width.

## Phase 5 — Evaluation

**Tasks**
1. Create `eval/golden-questions.json`: an array of `{ "id", "question", "expectedAnswerContains": [..], "expectedSourceTitles": [..], "answerable": true|false }`. Include 5 placeholder examples; the developer will extend to 20–30.
2. `PolicyAssistant.Evals` console app that:
   - Calls the running API for each question.
   - Computes simple deterministic metrics: retrieval hit rate (expected source cited), keyword match rate, correct refusal rate for unanswerable questions.
   - Optionally scores groundedness and relevance with an LLM-as-judge prompt against the same chat deployment (behind a `--judge` flag).
   - Writes a timestamped results file (JSON + a Markdown summary table) to `eval/results/`.
3. Document how to run evals in the README, and note that Foundry's built-in evaluators can be used as an alternative.

**Acceptance criteria**
- `dotnet run --project tests/PolicyAssistant.Evals` produces a results summary against a running API.

## Phase 6 — Conversation history (follow-up questions)

**Tasks**
1. Web sends the last N turns (configurable, default 6) in `ChatRequest.History`.
2. Before retrieval, if history is present, call the chat model with a short "rewrite the follow-up into a standalone search query" prompt; use the rewritten query for retrieval and the original question for generation.
3. Include recent history in the generation messages.
4. Unit test: with history present, the retriever receives the rewritten query.

**Acceptance criteria**
- Asking "How many days of annual leave do I get?" followed by "What about part-time staff?" retrieves relevant part-time leave content.

## Phase 7 — Streaming (optional)

**Tasks**
1. Add `POST /chat/stream` using `CompleteChatStreamingAsync`, streaming tokens via Server-Sent Events, with citations sent as a final event.
2. Update the UI to render tokens as they arrive.

**Acceptance criteria**
- Answers appear progressively in the UI; citations appear when the stream completes.
